# 캔버스 메모 모음 (화면별 설명)

캔버스에서 각 화면 아래·옆에 붙어 있던 메모를 그대로 옮긴 것입니다. 파란 메모는 화면 설명(FE 담당이 직접 고쳐 쓴 내용 포함), 주황 메모는 변경 이유·비교 설명입니다.

출처 표시: [데이터] 공개 CSV 원본 값 · [모델] 백엔드가 계산한 값 · [매뉴얼] 문서 검색 결과 · [사람] 사용자가 입력한 값 · [미정] 팀이 정해야 하는 값

- 줄 제목: 새 버전 ③ 마무리 · 옆길 · 부록 — 정비일지 · 이력 · 수동 · 현장 확인 · 인계 · 설비 · 공통 상태

### 어떻게 정리했나 (주황)

어떻게 정리했나
1. 한 화면에 할 일 하나 (점검 → 판단 → 조치 → 결과)
2. 자세한 건 눌렀을 때만 — "이상"을 고르면 측정값 · 할 일이 펼쳐짐
3. 참고 정보는 오른쪽 패널 탭으로 — 상황 / 원인 / 기록
4. 매뉴얼은 버튼 하나 → 그 자리에 PDF 원본 페이지

되살린 기능
- 작업함: 검색 · 필터 · 담당 · 반복 묶음 · 설비 상태
- 상황: 기간 · 신호 선택 · 용접 멈춤 구간 · 데이터 상태
- 점검: 측정값 · 메모 · 사진 · 이상일 때 할 일 · 주의 한 줄
- 공통: 원인 목록과 상태 · 시간순 기록 · 임시 저장 · 현장 확인 입력 · 도움 요청
- 조치: 매뉴얼 조치 불러오기 · 부품 · 작업자 · 시각
- 정비일지 · 이력 · 수동 · 현장 확인 · 인계 화면

일부러 뺀 것
- 출처 배지, AI 요약 카드, 근거 인용문 목록 (→ 매뉴얼 버튼)
- 조치 후 확인 화면 (전후 그래프)

참고한 서비스 화면 방식
- 점검 항목 통과 / 이상 버튼 (MaintainX)
- 작업 상세 + 옆 패널 탭 (UniFocus)
- 상태 구분 · 부품 · 사진 · 기록 (CLUE)

흐름 점검 뒤 고친 것
- 끊긴 버튼 연결 (결과 → 정비일지 등)
- 수동 모드로 들어가는 길 2개
- 원인이 다 떨어졌을 때 화면
- 그래프는 그 자리에서 크게
- 판단은 카드 한 번으로
- 일지 승인 → 해결 종료 순서 고정

화면 속 값은 모두 예시. 아래 줄부터는 이전 버전.

## 추가 메모 (주황)

회의 피드백으로 바꾼 것 (요약)
1. 사람의 1차 판단(실제 이상 / 오탐 / 모니터링) 뺌 → LLM 결과가 트리거
2. 원인 후보·점검 + 판단 + 조치 기록을 한 화면으로 → 후보마다 반복
3. 재검증 화면 뺌 → 결과 칸 + 자동 표시 한 줄

화면 수: 7단계 → 4단계 (작업함 → 원인 찾기·조치 → 정비일지 → 이력)

### (보관) ⑤ 재검증  (`boards/Verify.dc.html`, 1440×1080)

**화면 설명**

⑤ 재검증 — 고친 뒤 정상으로 돌아왔는지 확인
보이는 정보: 조치 전 그래프 [데이터] · 조치 후 그래프 [시뮬레이션] · 판정 규칙과 시스템 판정 [모델] · 사람 판단 [사람]

화면구성
- 조치 전/ 조치 후: 왼쪽 "조치 전": 고장 2시간 전부터 고장 순간까지 test_0의 실제 데이터 / 조치 후: 시뮬레이션 가상 데이터

- 시스템 판정 - 판정은 5가지로 일단 분류 
- 판정 5가지 - 정상복귀 (규칙 모두 충족) / 개선 (나아졌지만 기준미달) / 미해결(변화 없음) / 판정대기(기준 수집중) / 판정 불가 (데이터없는 등)
- 사람 판단칸 - 현장 사람이 직접 본 결과 

주의: 공개 데이터엔 고친 뒤 구간이 없어 시연에선 '시뮬레이션' 표시가 필수. 판정 기준값(N 등)은 [미정]

# 와이어프레임

캔버스에서 그린 와이어프레임의 복사본. **새 버전(`V2*`, 2026-10-08 기준)이 지금 구현 기준**이고, 나머지는 이전 버전(10-02)이다.

## 폴더

| 경로 | 내용 |
|---|---|
| `screenshots/*.png` | 화면별 그림. 먼저 이걸 본다 |
| `boards/*.dc.html` | 화면별 HTML 원본. 브라우저로 바로 열 수 있다 (정적 목업, 동작 없음) |
| `canvas-notes.md` | 캔버스에 붙어 있던 화면별 설명 메모 (FE 담당이 직접 고쳐 쓴 내용 포함) |
| `canvas.json` | 캔버스 배치 정보 (화면 위치·제목·메모 원본) |

이 HTML은 구현 코드가 아니라 **무엇을 보여줄지 정한 목업**이다. 색·간격·컴포넌트 이름을 그대로 옮길 필요는 없다.
화면 안의 값은 예시이고, `[이름]`, `[데이터 시각]`, `[작업 시각]` 같은 대괄호는 아직 정해지지 않은 자리다.

## 현재 흐름 (새 버전 · 10/3 멘토링 피드백)

기능은 이전 버전과 같고, **한 화면에 할 일 하나**로 나눴다. 케이스 화면에는 위에 진행 표시(점검 → 판단 → 조치 → 결과), 오른쪽에 패널 탭(상황 / 원인 / 기록)이 있다.

```
작업함 ──▶ 상황 ──▶ 점검 ──▶ 판단 ──▶ 조치 ──▶ 결과 ──▶ 정비일지 ──▶ 정비 이력
                     ▲        │                   │
                     │        ├─ 아니에요 ─────────┼──▶ 다음 원인 점검 (원인이 다 떨어지면 → 남은 원인 없음)
                     │        └─ 잘 모르겠어요 ──▶ 도움 요청
                     └─ 현장 확인 입력 (직접 재고 돌아옴)
매뉴얼 안내 없음 ──▶ 수동 모드 (직접 점검 기록)
```

## 화면 목록 (새 버전)

### 핵심 흐름

| 파일 | 화면 | 역할 |
|---|---|---|
| `V2Main` | 작업함 | 처리할 고장 목록. 경보 · 설비 · 고장 코드 · 예상 유형 · 발생(데이터 시각) · 상태 · 담당. 점검 중이면 "이어서" |
| `V2Case` | 상황 | 무슨 일이 났나: 최근 30분 그래프, 신호 선택, 확인할 원인 목록, "점검 시작" |
| `V2Check` | 점검 | 항목마다 정상 / 이상 / 건너뜀. "이상"이면 메모 칸과 "이상일 때 할 일"이 펼쳐짐 |
| `V2Manual` | 점검 · 매뉴얼 보기 | 매뉴얼 버튼을 누르면 오른쪽 패널 자리에 PDF 원본 쪽이 열림 |
| `V2Judge` | 판단 | 점검 결과 요약을 보고 맞아요 / 아니에요 / 잘 모르겠어요 중 하나를 누름 |
| `V2Action` | 조치 | 조치 종류, 한 일, 교체 부품, 작업자, 시작 · 종료(작업 시각), 사진. 정비일지에는 여기 적은 내용만 들어감 |
| `V2Result` | 결과 | 해결됐어요 / 다른 조치 / 다음 원인. 지금까지 한 일(점검 · 판단 · 조치)을 보고 고름 |
| `V2Log`, `V2LogDone` | 정비일지 (승인 전 · 후) | "일지 승인"이 먼저, 승인 전에는 "해결 종료"가 잠김 |
| `V2History` | 정비 이력 | 닫힌 고장 목록(읽기 전용), 걸린 시간 |

### 원인이 아닐 때

| 파일 | 화면 | 언제 |
|---|---|---|
| `V2Check2`, `V2Judge2` | 다음 원인 점검 · 판단 | 판단에서 "아니에요" 또는 결과에서 "다음 원인 확인" |
| `V2NoCause` | 남은 원인 없음 | 모든 원인이 "아니에요"일 때. 직접 점검 기록 / 도움 요청 / 원인 다시 보기 |

### 옆길 · 부록

| 파일 | 화면 | 언제 |
|---|---|---|
| `V2NoGuide` | 수동 모드 | 맞는 매뉴얼 안내가 없을 때. 점검 순서를 지어내지 않고 사람이 확인한 것을 적음 |
| `V2Field` | 현장 확인 입력 | 센서로 알 수 없어 직접 재야 할 때. 저장하면 점검으로 돌아감 |
| `V2Handover` | 도움 요청 (인계) | 받는 사람 · 급한 정도 · 이유 · 내용. 지금까지의 기록이 함께 전달됨 |
| `V2Equip` | 설비 | "지금 이 설비를 판단할 수 있나" — 열린 고장, 기준 수집 중, 판단 보류 |
| `V2States` | 공통 상태 (개발용) | 불러오는 중 · 불러오지 못함 · 목록 비었음 · 데이터 끊김 · 매뉴얼 못 엶 · 저장 못 함 |

## 새 버전에 반영한 FE 결정 (10/8)

- **시각:** "오늘 · 몇 분 전" 대신 데이터 시각(한국 시간)을 쓴다. 공개 데이터 시각이 2019~2021년이라 상대 시각을 만들 수 없다. 고장 시각(데이터 시각)과 사람이 작업한 시각(작업 시각)은 이름표로 구분한다.
- **로그인 없음:** "담당 · 나"는 쓰지 않는다. 작업자 · 확인자는 직접 입력한다.
- **그래프:** 최근 30분 고정 (기간 버튼 없음). ML 핸드오프의 `sensor_trend`가 30분이다. "그래프 크게 보기" 화면은 뺐다.
- **고장 코드와 예상 유형은 다른 칸.** 코드(E012)는 제어기가 남긴 사실이고, 유형은 데이터셋 기준 추정이다.
- **점검 "이상" → 메모 칸.** 항목별 단위 · 기준값은 RAG 데이터에 없어서 측정값 · 단위 · 기준값 칸을 따로 두지 않는다 (`../docs/06-rag-response-format.md`와 같은 기준).
- **지금은 안 만드는 것:** 작업함 상태별 필터 칩, 재생 콘솔.
- **`test_1`(코드 없음) 행:** 수동 모드로 가는 길을 보여주는 화면 예시다. 실제 데이터가 아니라 mock에는 넣지 않는다.
- **아직 데이터가 없는 것:** 점검 항목별 매뉴얼 쪽수(RAG 요청 3), 매뉴얼 PDF 원본 보기(api가 PDF를 내려줘야 함), 수동 모드의 매뉴얼 검색(RAG에 키워드 검색 없음). 화면의 쪽수 · 검색 결과는 예시다.

## 화면 공통 규칙

- 색은 경보(빨강·주황)에만 쓰고 나머지는 차분하게.
- 컨트롤러 코드(E012), 데이터셋 클래스(E01), 매뉴얼 오류 번호(Festo 12)는 서로 다른 칸에.
- 매뉴얼 조치는 초안으로만 불러오고, 정비일지에는 사람이 실제로 한 일만 들어간다.
- 매뉴얼 안내가 없으면 수동 모드로 바꾸고 점검 순서를 지어내지 않는다.
- 현장 확인 입력 · 도움 요청은 어느 단계에서든 누를 수 있다.

## 이전 버전 (10-02 · 비교용)

새 버전으로 바뀌기 전의 화면이다. 파일은 그대로 두었다.

| 파일 | 화면 |
|---|---|
| `Main` | ① 작업함 |
| `Resolve`, `Resolve1`, `Resolve2` | ② 원인 찾기·조치 (한 화면 통합안, 비교 1안 · 2안). 1안으로 정했다가 새 버전으로 대체 |
| `Logbook`, `History` | ③ 정비일지·종료, ④ 정비 이력 |
| `Manual`, `FieldCheck`, `Handover` | 수동 모드, 현장 확인 체크시트, 인계서 |
| `Equipment`, `Replay`, `States` | 설비 상태, 재생 콘솔(데모용), 공통 상태 |
| `Scenario`, `Flow`, `Learn`, `Research`, `Layout` | 설명용: 사용 시나리오, 흐름 지도, 용어와 장비, 리서치 |
| `ApiRepo`, `ApiCase`, `ApiRag` | API 보드 3장. 옛 레포(48harry/U3) 기준이라 낡았고 캔버스에서는 지웠다. 최신은 `../docs/05-fe-api-requests.md`, `../docs/06-rag-response-format.md` |
| `Triage`, `Guide`, `Action`, `Verify` | 그보다 앞선 7단계 흐름의 화면 (상황 파악, 원인 후보·점검, 조치 기록, 재검증) |

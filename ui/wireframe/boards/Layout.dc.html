화면구조

대시보드 레이아웃(왼쪽 메뉴 + 목록 + 상세)을 빌리되, 첫 화면은 숫자판이 아니라 할 일 목록(작업함)으로 둔 이유.

1

보는 화면이 아니라 처리하는 화면

  • 사용자가 할 일: 알람 확인 → 점검 → 조치 → 기록. "지표 보기"가 목적이 아님
  • 그래서 첫 화면은 요약 숫자 카드 대신 작업함(할 일 목록)
  • 케이스를 열면 2단계 진행 표시(원인 찾기·조치 → 정비일지)를 따라 한 건을 끝까지 처리
2

업계에서 쓰는 구조: 목록 → 케이스 상세

  • Siemens Senseye(예지보전): "케이스" 관리, 이상 구간을 표시한 시계열 그래프, 가능한 원인 설명, 비슷한 과거 케이스 연결
  • 설비 정비 관리 제품(MaintainX 등): 작업지시서 목록이 중심
우리 ② 원인 찾기·조치(신호 그래프 · 원인 후보 · 근거) · ④ 정비 이력과 같은 짜임
3

기계 옆 조작 화면이 아니라 웹

  • 설비 옆 조작 화면(HMI)은 기계를 운전 · 제어하는 용도
  • 우리는 "무엇이 고장났고 어떻게 고칠지"를 판단하고 기록하는 서비스
  • 담당자 · 전문가가 같은 케이스를 봐야 함(인계) → 설치 없이 링크로 여는 웹이 맞음
4

익숙한 레이아웃 

  • 왼쪽 메뉴 + 목록 + 상세는 업무용 웹에서 가장 흔한 배치 (BankDash · DashStack 키트는 느낌만 참고)
  • 색은 경보(빨강 · 주황)에만 쓰고 나머지는 차분하게 → ① 운전 화면 표준과 같은 방향

화면 계층 대응

ISA-101의 4단계 계층 ↔ 우리 화면
단계표준에서 말하는 화면우리 화면
1전체 현황① 작업함 (처리할 케이스) · 설비 상태 (판단 가능 여부)
2하위 설비작업함 · 이력의 설비 필터

4진단② 원인 찾기·조치 후보 카드 (점검 · 판단 · 조치 · 매뉴얼 근거)

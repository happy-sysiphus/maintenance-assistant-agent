② 원인 찾기 · 조치 화면의 핵심
보내는 것코드 · 클래스 힌트 · 이상 신호 (레포 /predict 값) + 지금까지의 점검 결과 + 후보별 판단 (맞음 / 아님 / 모르겠음) → 아님이면 제외하고 다시 정렬
받는 것아래 모양 (값은 예시)
{
  "version": 2,
  "mode": "guide",            // guide | manual (근거 없으면 manual)
  "candidates": [
    { "id": "C1", "name": "보정 압력 계통", "rank": 1,
      "status": "supported",    // reviewing | supported | excluded
      "signals": ["c5"], "evidence": ["EV-01"] }
  ],
  "checklist": [
    { "id": "K1", "title": "공급 압력 확인 (최소 5 bar)",
      "input": "number", "unit": "bar", "evidence": "EV-01" }
  ],                          // input: number | select | text
  "evidence": [
    { "id": "EV-01", "doc": "Festo Servopneumatic V1.5",
      "section": "§10.1 Table 10.1", "page": 90,
      "quote": "Check supply pressure at least 5 bar.",
      "grade": "structural",    // direct | structural | compare
      "reason": "구동 방식 같음 · 모델 미확인" }
  ],
  "summary": { "text": "…", "cites": ["EV-01", "EV-02"],
               "source": "ai" } // manual 모드면 null
}

POST/cases/{id}/logbook/draft

일지 초안. 칸 대부분은 템플릿 채우기로 충분하고, LLM은 "문제 내용" 문장 다듬기에만 쓰는 안 추천

공통 약속

  • 시각 · 모두 UTC ISO 8601 (레포와 같음). 한국 시간 변환은 FE
  • source 필드 · 값마다 출처 표시: data / model / manual / human / ai / simulation → 캔버스 메모의 [데이터] [모델] 배지
  • 코드 3종 분리 · controller_code (E012) · class_hint (E01) · doc_error_no (Festo 12)를 다른 필드로
  • 새 알람 받기 · 몇 초마다 다시 묻기(polling)가 데모엔 가장 쉬움 · 서버가 밀어주기(SSE)는 선택
  • 오류 응답 · 조회 실패와 저장 실패를 구분, 동시 수정은 409 (공통 상태 보드)

백엔드와 정할 것

  • 원인 후보를 대응표로 만들지, 매번 RAG · LLM으로 만들지
  • 문서 적용 등급을 문서 등록 때 사람이 붙일지
  • LLM 호출 로그 + 사람의 후보 판단을 RAGAS 평가 데이터로 남길지
  • 점검 항목마다 if_abnormal (이상일 때 할 일) · 후보마다 path (온톨로지 근거 경로) 추가

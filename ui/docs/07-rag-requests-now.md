# 07. RAG 담당에게 — 지금 필요한 것 (2026-10-23)

2026-10-23 · FE 담당 (한혜원)

10/2에 보낸 요청(`06-rag-response-format.md`)이 아직 반영 전이라, **지금 화면을 연결하는 데 꼭 필요한 것만** 한 장으로 다시 정리했습니다. 06의 내용 중 아래에 없는 것은 급하지 않습니다.

기준: 레포 `main` `a6a1a95`(10/22). `rag/`의 마지막 커밋은 10/2(`b1a9db1`)입니다.

## 먼저 알아 두실 것 — ML이 10/21에 바뀌었습니다

ML 핸드오프가 v1.2가 되면서 **`situation_ids`(S01~S10)와 `symptoms`를 더 이상 보내지 않습니다** (`ml/README.md` 5.10, `ml/history.md` 33절).

- ML이 보내는 건 컨트롤러 코드(`fault_class.terminal_code`, 예: `E029`)와 고장 유형(`fault_class.code`, 예: `E04`)뿐입니다.
- 매분 센서 문서(sensor-features v4)가 새로 생겼고, ML 문서에는 "RAG가 받는 건 이 매분 문서 하나"라고 되어 있습니다 (`ml/docs/sensor_features_for_rag.md`).
- 같은 문서에 "S01~S04는 E01~E04와 같은 것이라 그대로 쓸 수 있고, **S05~S10은 데이터 근거가 없어 쓰지 않는다**"고 적혀 있습니다.
- 지금 `answer_question(situation_ids, question)`은 S ID를 입력으로 받으므로, **입력을 무엇으로 받을지 RAG 쪽 결정이 필요합니다.**

FE 화면은 지금 "상황 ID 하나 = 원인 후보 하나"로 만들어져 있습니다(S05~S09가 원인 후보). S05~S10을 안 쓰게 되면 원인 찾기 흐름이 바뀌므로, 아래 1번을 먼저 정해 주세요.

## 요청 (우선순위 순)

### 1. (필수) 입력: E 코드로 부를 수 있게 + 원인 후보를 어떻게 줄지

다음 중 어느 쪽인지 알려 주세요.

| 안 | 입력 | 원인 후보 |
|---|---|---|
| A | `answer_question(error_code="E029", question=…)` | RAG가 E 코드 → S01~S04 → 연결된 원인 상황(S05~S09)을 함께 찾아 줌 |
| B | 지금처럼 S ID | api가 E 코드를 S01~S04로 바꿔서 부름. 원인 후보는 S01~S04 답 안의 "원인 후보"만 씀 |

FE는 A를 바랍니다. 화면의 "원인 후보 → 점검 → 맞나요?" 흐름을 유지할 수 있습니다.

### 2. (필수) 예시 출력 JSON을 레포에

Neo4j · OpenAI 키 없이 FE와 api가 개발할 수 있게, 실제 실행 결과를 파일로 올려 주세요. E012 · E016 · E028 · E029 네 개면 충분합니다.

```bash
python -m rag ask --situation-ids S04 --question "이 상황의 원인 후보와 점검 순서를 알려주세요." --json --output rag/docs/S04.example.json
```

### 3. (필수) 답을 칸으로 나눠서 — 특히 "어떻게 고치나(조치)"

지금 `answer`는 제목 4개(오류 상황 해석 / 원인 후보 / 점검 체크리스트 / 답변 요약)가 있는 마크다운 한 덩어리이고, **조치는 "원인 후보" 문장 안에 섞여 있습니다.** 조치 화면에 "어떻게 고치나"를 한국어로 보여주려면 조치만 따로 받아야 합니다. 기존 `answer`는 그대로 두고 아래 필드만 추가해 주시면 됩니다.

```json
{
  "status": "ok",
  "answer": "## 오류 상황 해석\n…(지금 그대로)…",
  "sections": {
    "interpretation": "…",
    "summary": "…"
  },
  "causes": [
    {
      "situation_id": "S08",
      "name": "…",
      "why": "왜 이 상황과 관련되는지 (한두 문장)",
      "checks": [
        {
          "text": "점검 행동 한 줄",
          "cite": { "doc": "rsw", "page": 6 },
          "criterion": { "text": "정상 기준 (예: 공급 압력 5 bar 이상)", "cite": { "doc": "festo", "page": 90 } }
        }
      ],
      "actions": [
        {
          "when": "이 조건일 때 (예: 점검 결과 …이면)",
          "text": "할 일 한 줄",
          "cite": { "doc": "festo", "page": 90 }
        }
      ]
    }
  ],
  "evidence": ["…(지금 그대로)…"]
}
```

- 위 값은 모양 예시입니다. 내용은 지금 설명문(프롬프트) 규칙 그대로 — **매뉴얼에 없는 조치는 넣지 않고, 없으면 `actions: []`** 로 주시면 화면은 "매뉴얼에 조치 없음"으로 보여줍니다.
- `cite`는 지금 답에 붙는 `[Festo PDF p.90]` · `[RSW PDF p.6]`을 나눈 것입니다. 화면은 이 쪽 번호로 PDF 원본을 엽니다.
- 설명문에 출력 형식만 JSON으로 바꾸는 방법(구조화 출력)도 됩니다. 편한 쪽으로 해 주세요.
- **점검 항목마다 정상 기준(`criterion`)이 필요합니다 (10/23 추가).** 작업자가 "본관 공급 압력 측정"을 할 때 몇이면 정상인지 알아야 정상/이상을 고를 수 있습니다. 매뉴얼에 숫자가 있으면 숫자와 쪽, 없으면 확인 방법, 그것도 없으면 빈 값으로 주세요.
- 기다리는 동안 FE가 **초안 표**를 만들어 화면에 "매뉴얼 참고값 · 확인 전"으로 쓰고 있습니다: `api/check_criteria.json` (S01~S04 점검 항목 17개 중 15개, 원문 문장과 쪽 포함). **항목과 쪽을 맞게 짝지었는지 확인 부탁드립니다.** 틀린 줄은 고치거나 지워 주시면 됩니다.

### 4. AI 챗봇용 — 질문만으로 부르기

왼쪽 메뉴 "AI 챗봇"은 사용자가 상황을 고르지 않고 그냥 질문합니다 (예: "보정 압력이 늦게 올라오면 뭐부터 확인해?"). 지금은 벡터 검색이 없어서 질문 문장만으로는 매뉴얼을 못 찾습니다.

- 질문에서 상황을 고르는 방법(키워드 · 벡터 검색 · LLM 분류) 중 무엇이 가능한지
- 앞 대화(`history`)를 같이 넘기면 이어 묻기("그럼 다음엔?")에 쓸 수 있는지
- FE가 정한 요청 · 응답 모양: `05-fe-api-requests.md` 맨 아래 "AI 챗봇 API" 절

### 5. 확인 부탁

- 답 하나 만드는 데 몇 초 걸리는지 (10초가 넘으면 화면에 진행 표시를 따로 둡니다)
- RSW 상황 정의서 PDF(`rag/data/rsw_situations.pdf`)를 화면에서 원본으로 보여줘도 되는지 (지금 FE 개발 서버와 api 초안이 이 파일을 `/api/manuals/rsw.pdf`로 내려주고 있습니다)

### 6. (필수) api에서 RAG를 부르려면 — 받아야 할 것

api 담당이 없어서 FE가 데모용 api 초안을 `api/`에 올렸습니다 (`08-api-draft.md`). 지금은 `rag/data/situation_mapping.json`만 직접 읽고, `answer_question()`은 아직 부르지 않습니다. **RAG를 붙일 자리는 `api/guidance.py` 한 파일**이고, FE 로컬에서 RAG를 돌리려면 아래가 필요합니다.

**`rag/.env`에 넣을 값** (`rag/.env.example` 기준)

| 변수 | 필요한 이유 |
|---|---|
| `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `NEO4J_DATABASE` | 매뉴얼 그래프 조회 |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | LLM 한국어 답 (없으면 `use_llm=False` 근거만 조회) |

**알려 주세요**

1. **Neo4j는 어디에 있나요?** 예시 주소가 `bolt://localhost:7687`이라 담당자 PC에만 있는 것으로 보입니다.
   - 클라우드(Aura 등)라면 → 접속 정보를 개인 메시지로 주세요.
   - 본인 PC에만 있다면 → FE가 자기 PC에 Neo4j를 설치하고 README의 `parse → chunk → ingest → build`로 같은 그래프를 만들어도 되는지, `build --skip-llm`으로 해도 답 품질이 같은지 알려 주세요.
2. **OpenAI 키는 누구 계정으로 쓰나요?** 팀 공용 키가 있는지, 데모 때 호출해도 되는 범위가 있는지.
3. 비밀번호 · 키는 깃에 올리지 말고 개인 메시지로 주세요. FE가 직접 `rag/.env`에 넣습니다 (`.env`는 깃에서 제외됨).

## 안 하셔도 되는 것

- 웹 서버: api 서버(`api/`, FE 초안)가 파이썬 함수로 직접 부릅니다.
- PDF 파일: 레포의 `rag/data/*.pdf`를 api가 화면에 내려줍니다. RAG는 **몇 쪽을 볼지(쪽 번호와 연결)**만 주시면 됩니다.
- 화면용 순서 · 상태 · 버전: api가 붙입니다.
- `status` 6종은 그대로 씁니다.

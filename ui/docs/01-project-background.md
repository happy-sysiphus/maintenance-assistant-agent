## 서비스가 풀려는 문제 (기획서의 가설 — 현장 검증은 없음)

1. 설비에 이상이 생기면 담당자가 매뉴얼과 과거 이력을 직접 찾아야 하고, 숙련자에게 의존한다.
2. 문서를 그냥 검색하면 다른 모델이나 구버전의 절차가 섞여 나온다. (용접건 매뉴얼 5종도 구동 방식이 서로 다르다: 서보 공압식, 공압식, 전동 서보식)
3. 이상 판정까지 LLM에 맡기면 같은 입력에도 답이 달라진다.

그래서 역할을 나눈다: **ML은 탐지, 온톨로지는 적용 범위 거르기, LLM은 찾은 근거를 설명**.

## 기획서의 워크플로우 (7단계)

1. 센서 데이터 수집 (MVP는 공개 데이터를 시간 순서대로 재생)
2. ML 이상 탐지 — 이상 여부 + 어떤 신호가 어느 방향으로 벗어났는지
3. LLM 시작
4. 온톨로지 기반 RAG 검색 — 증상 → 원인 후보 → 점검 절차 → 근거 문서
5. 대응 조치 안내 — 점검 순서와 적용 조건을 근거 페이지와 함께
6. 점검 결과 입력과 안내 갱신 — 결과에 따라 후보를 좁힘, 필요하면 전문가 인계
7. 정비일지 — 초안 자동 작성, 엔지니어가 검토·확정

공통 원칙: **판단은 사람이 하고 시스템은 보조한다.** 장비 제어와 고장 원인 확정은 범위 밖이다.

## FE의 자리

- 사용자는 **정비 담당자(현장 엔지니어)**와, 인계를 받는 **전문가**다.
- 화면의 목적은 "지표를 보는 것"이 아니라 "고장 한 건을 처리하는 것"이다. 그래서 첫 화면은 숫자판이 아니라 작업함(할 일 목록)이다.
- 모든 값에 출처를 표시한다: 데이터 / 모델 / 매뉴얼 / 사람 / AI / 시뮬레이션.
- 근거가 없으면 지어내지 않고 사람에게 넘긴다 (수동 모드, 인계).

API ② 케이스 · 기록 (새로 필요)

제안 초안 · 백엔드와 합의 필요

화면 순서대로 FE가 부르는 API. 이름과 필드는 제안이고, "레포 값 사용" 표시는 /predict · /guns 결과를 가공해 쓰는 부분입니다.

방식주소보내는 것받는 것
① 작업함
GET/cases?status=&severity=&mine=필터케이스 목록: id, 설비, 트리거 코드, 클래스 힌트, 경보 등급, 진행 상태, 발생 시각, 담당 레포 값 사용
GET/cases/{id}—케이스 상세 + 현재 후보 · 단계
② 원인 찾기 · 조치 (통합 화면 · 안내 자체는 API ③ 보드의 /guidance)
GET/cases/{id}/signals?from=&to=&cols=구간 · 센서"무슨 일이 났나" 작은 그래프 + 전체 그래프 · 기여 신호 레포 값 사용
POST/cases/{id}/checks후보 id, 점검 항목 id, 결과 (정상 / 이상 / 미실시), 측정값 · 단위, 사유저장된 결과 → 이어서 /guidance 다시 호출
POST/cases/{id}/candidates/{cid}/judgment판단 (맞음 / 아님 / 모르겠음) + 사유후보 상태 · 아님이면 다음 후보 (RAG 평가 로그에도 저장)
POST/cases/{id}/candidates/{cid}/actions수행한 조치, 조치 유형, 교체 부품, 수행자, 시작 · 종료 시각조치 id (필요하면 백엔드가 DELETE /guns 호출 레포 API)
POST/cases/{id}/candidates/{cid}/result해결됨 / 해결 안 됨해결 안 됨이면 다음 후보 · 자동 표시용 "종료 코드 재발 여부" 레포 규칙 사용
③ 정비일지 · 종료
GET/cases/{id}/logbook—일지 초안 (칸마다 출처 태그)
POST/cases/{id}/logbook/approve수정한 일지승인자 · 시각 (서버 기록)
POST/cases/{id}/close종료 결과 (해결 / 미해결 저장 / 이상 없음) + 사유닫힌 케이스 → 이력으로 이동
인계 · 공통 · 이력 · 설비
POST/cases/{id}/handover인계 대상, 긴급도, 요청 사항, 첨부인계서 (자동 칸 포함) · 상태 "인계됨"
GET/cases/{id}/timeline—후보별 판단 · 조치 루프 기록 + 시각 (MTTR 계산에 사용)
GET/history?gun=&result=&period=필터닫힌 케이스 목록
GET/equipment—설비별 상태 = /guns + 마지막 판정 + 열린 케이스 수 레포 값 사용

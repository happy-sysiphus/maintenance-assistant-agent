사용 시나리오 · 정비 담당자가 E012 한 건을 처리하는 흐름

작업함에서 케이스를 열고 → 한 화면에서 후보마다 매뉴얼 근거 확인 · 판단 · 조치 · 결과를 반복하고 → 해결되면 일지를 남기고 닫습니다.

예시 케이스: test_0 · 컨트롤러 코드 E012 · 2021-09-11 02:46 UTC
1

작업함

"지금 처리할 게 뭐지?" 보는 것
  • LLM 판단으로 생성된 케이스 목록
  • 설비 · 코드 · 발생 시각
  • 경보 등급 · 추정 유형 · 진행 상태
하는 것
  • 급한 것(critical)부터 "열기"
무엇부터 볼지 정리됨. 반복 코드는 한 줄로 묶임
2

원인 찾기 · 조치

핵심 · 한 화면이전 안의 상황 파악 · 원인 점검 · 조치 기록 · 재검증을 합침
"이 후보가 맞나? 매뉴얼대로 고쳤더니 해결됐나?"
① 후보 펼침
  • 무슨 일이 났나 (코드 · 작은 그래프)
  • 매뉴얼 원문 · 쪽수 · 등급
  • 점검 항목 · 이상일 때 할 일
② 판단
  • 이 후보 · 매뉴얼 안내가 맞나?
  • 맞음 / 아님 → 다음 후보 / 모르겠음 → 현장 확인 · 인계
  • RAG 평가 데이터로도 저장
③ 실제 수행 조치
  • 권고는 초안으로만 불러옴
  • 조치 · 유형 · 부품 · 수행자 · 시각
④ 결과
  • 해결됨 → 정비일지
  • 해결 안 됨 → 다음 후보 (루프)
  • "종료 코드 재발 없음" 자동 표시
후보를 위에서부터 하나씩 확인 → 매뉴얼 근거로 바로 조치 → 안 되면 다음 후보. 모든 후보가 아니면 수동 모드 · 인계
3

정비일지 · 종료

"기록 남기고 끝" 보는 것
  • 자동 초안 (문제 → 원인 → 조치 → 못 한 점검 → 후보별 판단 · 결과 → 근거)
하는 것
  • ① 일지 승인
  • ② 해결 종료
두 번 적지 않음
4

정비 이력

"지난번엔 어떻게 했더라?" 보는 것
  • 닫힌 케이스 (읽기 전용)
  • 후보별 판단 · 조치 타임라인
반복 고장 확인 · 지난 조치 참고

막혔을 때 가는 길

기본 흐름 중간 어디서든 갈라졌다가 다시 합류
이런 상황이면이 화면으로거기서 하는 것
매뉴얼에 맞는 근거가 없음 (코드 없이 모델 경보만 등)수동 모드 ② 자리에 자동으로 뜸근거 없는 이유 확인 · 문서 직접 검색 · 자유 점검 기록
센서로 알 수 없어 직접 재야 함현장 확인 체크시트PDF로 들고 가서 측정 → 결과 입력하면 ② 안내 갱신
혼자 해결 못 함 (권한 · 판단 부족 · 후보를 다 봐도 해결 안 됨)인계서대상 · 요청 사항만 적으면 점검 결과 · 제외 후보는 자동 → 전문가가 이어서 진행

팀원에게 전할 핵심 세 줄

1

정비 담당자는 "보는" 게 아니라 "처리"한다. 첫 화면은 할 일 목록, 케이스는 한 화면에서 후보마다 판단 · 조치를 반복해 끝낸다.

2

②에서 매뉴얼 근거로 점검과 조치를 바로 받고 사람이 맞는지 판단하는 것이 핵심 가치. 근거가 없으면 지어내지 않고 사람에게 넘긴다.

3

모든 값에는 출처가 있다 — 데이터 · 모델 · 매뉴얼 · 사람 · AI를 구분해서 보여준다.

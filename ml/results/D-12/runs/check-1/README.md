# D-12 실제 확인 한 번 (check-1, 2026-11-13)

작업자가 닫은 조기 경보 케이스의 판정이 api에서 ML 루프의 다음 학습까지 흘러가는지를 실제 데이터와 실제 서버로 한 번 확인했다. 설계: `docs/superpowers/specs/2026-11-12-feedback-labels-design.md` 9절. 명령과 출력은 `run.log`, 마지막 `status`는 `status.txt`, api가 내준 응답은 `api_feedback.json`이다.

**이 확인이 보여 주는 것은 "판정이 학습까지 흘러간다"까지다.** 여기서 누른 판정은 2019년 데이터를 재생해 나온 경보에 대한 것이고 실제 점검 결과가 아니다. 모델이 좋아졌다는 근거가 아니다.

## 기록에 남은 것

`models/registry-d12/registry.json`의 `versions.v001.feedback`:

```json
{"confirmed": 1, "false_alarm": 0, "unknown": 0, "unmatched": 0,
 "event_ids": ["8f1026ac6481f05498a61b387c5b9e3a"],
 "spans": 1, "windows_excluded": 60, "windows_already_not_normal": 0, "false_alarm_conflicts": 0}
```

`train.py`에 넘어간 구간(`v001/feedback.json`): `E02_1`의 `2019-12-19T06:15:00` ~ `07:15:00`.

이 확인 뒤 같은 날 검토에서 구간의 시작을 "경보가 시작된 창"으로 고쳤다(api가 `onset_at`을 함께 주고 `train.py`가 구간을 창 크기로 내림한다. `history.md` 51절). 이 건은 한 요청에 창 하나씩 흘렸고 경보 창이 `06:15:00` ~ `06:15:59`라 구간은 그대로다. `api_feedback.json`은 고치기 전의 응답이라 `onset_at`이 없다.

`status`:

champion    v001  trained at 2021-09-06T00:00:00 on 16 files

## 같은 16건 · 같은 시드로 학습한 첫 모델 셋

| | 학습 정상 창 | 알림 임계값 | 조기 경보 임계값 | 조기 경보 기준 창 | CV 건별 AUROC 평균 |
|---|---|---|---|---|---|
| 판정 없음 (replay-1, 11-12) | 99,414 | 0.954233 | 0.978946 | 116,280 | 0.8272 |
| 판정 없음 (오늘, 바뀐 코드) | 99,414 | 0.954233 | 0.978946 | 116,280 | 0.8272 |
| 판정 1건 반영 | 99,357 | 0.943697 | 0.946516 | 116,220 | 0.7916 |

읽는 법:

- **판정이 없으면 결과가 그대로다.** 바뀐 코드로 판정 없이 학습한 모델은 11-12의 모델과 임계값이 소수점 끝자리까지 같다(0.9542333546890804, 0.9789456129074097).
- **판정 1건은 창 60개를 뺐다.** 조기 경보 기준 창이 정확히 60개 줄었다. 학습 정상 창은 57개 줄었다. 나머지 3개(06:15, 06:38, 07:00)는 비용접 구간이 섞인 창이라 원래 학습에서 빠진다(구간의 창 60개를 전처리 파일에서 직접 세어 확인했다).
- **빠진 것은 0.06%인데 모델은 눈에 띄게 달라졌다.** 조기 경보 임계값이 0.979 → 0.947, CV 건별 AUROC 평균이 0.827 → 0.792로 움직였다. 판정 1건 · 시드 하나로 한 번 본 것이다. 같은 날 대조 실험(`../control-1/`)에서 경보와 관계없는 정상 한 시간을 같은 수만큼 빼 보니 세 번 모두 비슷한 크기로 움직였다(조기 경보 임계값 0.953 ~ 0.986, CV 건별 AUROC 0.792 ~ 0.823). 이 변화는 그 한 시간이 특별해서가 아니라, 행이 조금 빠지면 학습이 달라지기 때문으로 보인다.
- **이 차이를 좋아졌다 · 나빠졌다로 읽으면 안 된다.** 판정 1건의 변화는 아무 창 60개를 뺄 때의 흔들림과 구별되지 않는다(`../control-1/`). 이 크기가 시드를 바꿀 때의 변동과 같은지는 재지 않았다(D-11에서 잰 0.03 ~ 0.14는 섀도 AUROC의 시드 변동이라 다른 양이다). A/B 판정의 시드 모델이 이 변동을 덮는지도 확인하지 않았다.

## 한계

- 성공 기준 1(학습 쪽)만 확인했다. A/B 판정의 반영 전후 수치(성공 기준 2)는 자동 테스트로만 확인했다.
- 판정은 사람이 화면에서 누른 것이 아니라 api 주소를 직접 불러 남겼다. 화면(`ui/`)은 건드리지 않았다.
- 사람 판정은 지금 모델이 경보를 낸 구간에만 생기므로 A/B 판정을 지금 모델 쪽으로 기울인다(설계 7절).

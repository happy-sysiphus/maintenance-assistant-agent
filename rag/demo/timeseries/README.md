# 조기 경보 정비 이력 재사용 데모

이 데이터셋은 ML 예시 5개의 v1.4 구조, 초 단위 변화점, 센서별 값 범위와 변화 형태를 참고해 만든 **합성 경보 4건**이다. 별개 에피소드의 원시 블록은 각각 `c1`~`c19`와 결측 정보를 포함한다. E코드 없는 경로를 비교하기 위해 네 입력 모두 장비 보고 코드 없이 구성했다. 정비 내용과 해결 결과는 시연용 가정이다.

## 시나리오와 기대 결과

| 입력 | 파형에서 볼 것 | 시연할 작업 | 기대 |
|---|---|---|---|
| A 첫 압력 저하 | 닫기 명령(`c18`)과 힘 변화(`c2`)가 두 번 나타나고, 압력(`c5`)이 떨어졌다 일부 회복한다. | 이력이 빈 상태에서 후보를 요청하고, 필요하면 직접 매뉴얼을 검색한다. 작업자가 정비했다고 가정한 뒤 `manual:E012-C1`과 실제 조치란을 함께 저장한다. | `unseen` |
| B 같은 조치가 적용되는 재발 | A와 비슷한 압력·명령·힘의 변화가 약간 다른 시각과 값으로 나타난다. | 과거 카드에서 A의 조치와 PDF 근거를 보고 첫 점검을 선택한다. | `seen` → A |
| C 압력은 비슷하고 위치 변화가 다른 경보 | 압력 파형은 A와 비슷하다. 닫기 명령과 힘은 0으로 유지되고 전극 위치(`c3`)는 한 방향으로 서서히 변한다. | A의 압력 조치가 적용 가능한지 검토한다. 드리프트 관련 매뉴얼을 찾아 별개 조치로 해결했다고 가정하고 `manual:E029-C1`과 함께 저장한다. | `unseen` 또는 `uncertain`. A를 제시하면 오추천으로 집계한다. |
| D 위치 유지 이상 재발 | C와 비슷하게 위치가 서서히 변한다. 관측 초 2개가 비어 있다. | A와 C가 모두 등록된 상태에서 C의 실제 조치와 PDF 근거를 찾아 표시한다. | `seen` → C |

각 입력의 `expected`는 데모에서 확인할 정답이다. `simulated_resolution`은 작업자의 해결 종료 동작을 재현하는 데이터다. 재생기는 두 필드를 RAG의 판정에 전달하지 않으며, A와 C의 정비 기록은 해당 경보의 판정과 매뉴얼 조회가 끝난 뒤 저장한다. B의 판정에는 A만, D의 판정에는 A와 C가 보인다.

## 재생 방법

팀 Aura와 Claude·임베딩 설정이 있는 환경에서 저장소 루트 기준으로 실행한다.

```powershell
python -B -m rag.demo.timeseries.replay --output rag/var/warning-reuse-demo-v1-result.json
```

다른 작업본의 RAG 환경을 쓰는 경우 `--env-file`에 그 작업본의 `rag/.env` 경로를 지정한다. 실행할 때마다 Aura에 별도 이력 이름을 사용하고, 종료 후 해당 이름의 데모 노드를 정리한다. 결과 JSON에는 기대와 실제 판정, 유사도와 후보 ID, 매뉴얼 후보·수동 검색 응답, 해결 내용, 카드와 Aura 저장값의 일치 여부가 남는다.

## 이 데이터로 확인할 수 있는 것

- A의 해결 기록이 없을 때 매뉴얼을 검색하고, 저장한 뒤 B가 A의 과거 해결 카드에 접근할 수 있다.
- C는 A와 19채널 집계 유사도가 약 **0.978**이다. 높은 유사도에서도 위치·명령 파형의 차이를 보고 다른 정비가 필요한지 가려야 한다.
- D는 A와 C 중 적합한 이력을 골라야 한다. 데모 정답을 맞혔을 때는 카드의 조치·시각·출처가 실제 저장값과 일치하는지 확인한다.
- 작업자 시연에서는 B와 D에 대해 **매뉴얼만 볼 때와 이력 카드도 볼 때** 각각 첫 점검을 고르는 시간과 점검 적합성을 기록할 수 있다. 현장 정확도와 복구 시간 개선을 측정하려면 독립된 실제 경보, 정비 결과, 작업자별 측정 기록이 필요하다.

## 실제 재생 결과

| 입력 | Claude·Aura 실행 결과 |
|---|---|
| A | `unseen`. 자동 후보 1개는 전극 위치 하한 설정을 제안했다. 시나리오의 압력 점검은 수동 검색 단계에서 다뤘고, 지정된 합성 해결 이력을 저장했다. |
| B | `seen`. A를 골랐고 실제 조치와 PDF 근거가 Aura 저장값과 일치했다. |
| C | `unseen`. 유사도 0.978인 A를 재사용하지 않았다. 자동 후보는 전극 위치 감시 설정이었고, 시나리오의 드리프트 점검은 수동 검색 단계에서 다뤘다. |
| D | `seen`. A와 C 중 C를 골랐고 실제 조치와 PDF 근거가 Aura 저장값과 일치했다. |

A와 C의 수동 검색은 각각 PDF 근거 10개를 반환했다. 기대 판정과 사례 선택은 네 건 모두 일치했고, 종료 후 데모 노드는 0개였다.

ML 전송과 UI 클릭을 포함한 실행은 [통합 변경 보고서](../../../docs/timeseries-rag-integration-report.md)와 [브라우저 시연](../../../docs/timeseries-rag-browser-demo.html)에 정리했다.

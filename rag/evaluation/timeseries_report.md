# 시계열 RAG 평가 · 매뉴얼 후보와 해결 이력

2026년 11월 13~14일 · 통합 브랜치 `feat/timeseries-rag-demo` · 기준 커밋 `3f3b8c1`

합성 입력 **50건**으로 **E코드 없는 센서 입력에서 근거를 찾는 단계**와 **과거 해결 카드를 반환하는 단계**를 평가했다. 기존 RAGAS 50문항은 일반 매뉴얼 질의응답 평가다. 이번 실험은 제품이 반환한 근거와 카드를 미리 지정한 정답으로 직접 채점했다.

## 2. 새 경보에서 점검 근거를 얼마나 찾았나

센서 경보 25건을 만들었다. 20건에는 압력·위치·전극·힘 도달 신호·US2·마찰 관련 검토 근거를 연결했고, 5건은 해당 센서 관측만으로 구체적인 점검 근거를 고르기 어려운 경우로 구성했다. A와 C의 기존 합성 파형을 포함하며 나머지는 v1.4 변화점 형식으로 만들었다. 근거 라벨은 입력이나 검색어에 넣지 않았다. PDF 문서·페이지·문구를 미리 지정하고, 실제 PDF에서 일치하는지 확인했다.

- **검색 Precision@5**는 문항별 상위 다섯 결과 중 그 문항의 정답 근거를 포함한 PDF 조각의 비율이다. **Recall@5**는 정답 근거 총 22개 중 상위 다섯 결과에서 발견한 비율이다. 같은 근거의 여러 조각은 Recall에서 한 번만 센다.
- **자동 후보 Precision**은 Claude가 반환한 후보 중 정답 근거를 직접 인용하고 UI 응답 형식을 만족한 비율이다. **Recall**은 정답 근거 22개 중 후보에서 한 번 이상 확인한 비율이다. 후보가 비거나 생성에 실패하면 정답이 있는 문항에서 누락으로 집계한다. 형식은 제목·선정 이유·점검/조치 구분·PDF 원문·페이지·근거 ID를 확인했다.
- 채점은 문항별 지정 근거를 기준으로 한다. 다른 유효한 PDF 문구가 있어도 사전에 지정한 근거에 해당하지 않으면 점수를 받지 않는다. 정비 담당자의 현장 적합성 검토와 실제 원인 확정은 별도다.

| 실행 경로 | Precision | Recall |
|---|---:|---:|
| Aura 키워드 검색 상위 5건 | 2.61% (3/115) | 13.64% (3/22) |
| Aura 키워드·벡터 검색 상위 5건 | 3.48% (4/115) | 18.18% (4/22) |
| Claude 자동 후보 | 16.67% (2/12) | 9.09% (2/22) |

검색어는 현재 제품 코드가 알려진 센서 이름과 변화 상태를 이어 붙여 만든다. 서로 다른 경보에서도 구판 매뉴얼의 센서 표시 설명과 신판의 전극 감시 페이지가 상위에 반복됐다. 하이브리드 검색의 정답 근거 4개는 모두 전극 감시 문항에서 나왔다. **A의 보정 압력 점검과 C의 위치 드리프트 점검 근거는 검색 상위 5건에 들지 않았다.**

Claude 후보는 25건 중 12건에서 1개씩 나왔고, 12건은 후보 없음, 1건은 생성 오류였다. **반환한 12개 모두 UI 응답 형식을 충족했고, 모두 같은 전극 감시 페이지를 인용했다.** 이 중 문항의 정답 근거와 일치한 후보는 U10·U11의 두 개였다. U09·U12는 검색에 전극 감시 근거가 있었지만 최종 후보가 비었다. 압력·위치·힘 신호와 관련된 관측을 검색어에서 구분하는 문제와, 검색한 근거를 후보로 채택하는 문제를 이 결과에서 각각 확인할 수 있다. 현재 자동 경로에서 Claude의 역할은 검색된 PDF에서 후보를 고르는 것이다.

하이브리드 검색은 `text-embedding-3-small`, 후보 생성은 `claude-sonnet-5-5`를 사용했다. 문항당 1회 실행했으며, 출력 형식은 후보 응답 데이터에서 검사했다.

## 3. 정답 과거 이벤트를 선택했을 때 해결 카드를 정확히 가져왔나

공용 Aura의 임시 평가 영역에 합성 해결 이력 6종을 등록했다. 25건을 API 핸드오프로 넣고, RAG 판정 요청 후 UI가 사용하는 조회 API에서 카드를 가져왔다. 20건은 Claude 최종 선택만 미리 지정한 정답 이벤트로 대체했다. 정답 이벤트가 실제 검색 후보에 있어야 선택할 수 있고, 이후의 그래프 조회·응답 검증·카드 구성·API 조회는 제품 코드로 실행했다. 저장 요청의 기대값, Aura 저장값, API 카드의 10개 항목을 정확 일치로 비교했다.

| 검증 단위 | Precision | Recall |
|---|---:|---:|
| 정확한 해결 카드 | 100% (20/20) | 100% (20/20) |
| 카드 필드 | 100% (200/200) | 100% (200/200) |

카드 필드는 과거 이벤트 ID, 케이스 ID, 실제 조치, 종료 시각, 작업자 확인, 해결 결과, 매뉴얼 사례 ID, PDF 근거, 점검 단계, 조치 단계다. **대조군 5건 모두 카드 표시를 보류했다.** 대조군은 모델의 `unseen` 응답, 잘못된 선택 ID, 전체 결측, 미래 이력, 같은 에피소드의 과거 이력을 다뤘다. 이 수치는 정답 이벤트 선택을 전제로 한 카드 재현 성능이다. 현장 경보의 `seen/unseen` 판정은 실제로 확인된 현장 정비 데이터에서 따로 평가할 항목이다.

저장소 루트에서 RAG·API 의존성이 설치된 환경과 팀 Aura 설정으로 실행한다. `--hybrid`는 기존 임베딩 API에 합성 센서 검색어를 보낸다. `--live-candidates`를 켜면 합성 센서 소견과 검색된 매뉴얼 발췌를 Claude에도 보낸다.

```powershell
python -B -m rag.evaluation.timeseries --env-file rag/.env --hybrid --output rag/var/timeseries-eval/results.json
python -B -m rag.evaluation.timeseries --env-file rag/.env --hybrid --live-candidates --section unseen --output rag/var/timeseries-eval/live-candidates.json
```

평가기가 생성한 Aura 노드는 실행 후 해당 임시 영역에서 정리한다. 운영 정비 이력은 평가에 사용하지 않는다. 상세 JSON은 지정한 출력 위치에 남는다.
